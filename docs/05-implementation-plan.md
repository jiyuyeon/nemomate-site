## 2. 작업 우선순위

### 크리티컬 패스 (반드시 순서대로)
```
1-1 → 1-2 → 2-1 → 2-2 → 2-5 → 4-1
(프로젝트 세팅 → 토큰 → 레이아웃 → Hero → 다운로드 → 배포)
```
이 경로만 완성하면 **최소 기능 사이트**(Hero + 다운로드)가 동작한다.

### 병렬 가능 작업
- **1-4 (스크린샷 캡처)** ↔ **1-1~1-3 (프로젝트 세팅)** → 동시 진행 가능
- **2-3 (소개)** ↔ **2-4 (기능)** ↔ **2-6 (응원)** ↔ **2-7 (Footer)** → 2-1 완료 후 병렬

## 3. 리스크 & 완화 방안

| 리스크 | 영향 | 완화 |
|--------|------|------|
| 스크린샷 품질 부족 | 사이트 신뢰감 하락 | 캡처 전 게임 내 UI 정리, 일관된 창 크기로 촬영 |
| 베타 파일 크기 과대 | 다운로드 이탈 | GitHub Releases 무료 한도 확인 (2GB/파일), 필요 시 압축 |
| 모바일 비율 높으나 데스크톱 앱 | 설치 불가 → 이탈 | 모바일에서는 "PC에서 다운로드하세요" 안내 + 이메일 알림 유도 |
| 커스텀 도메인 미확보 | SEO/브랜딩 약화 | GitHub Pages 기본 URL로 시작, 추후 도메인 연결 |
| Giscus GitHub 로그인 필수 | 비개발자 댓글 어려움 | 로그인 없이 사용 가능한 폴백(Google Form) 병행 검토 |

## 5. 스크린샷 캡처 가이드

| 항목 | 설정 |
|------|------|
| **창 크기** | 480 x 520px (게임 기본 창 크기) |
| **배경** | macOS: 바탕화면 단색 배경 / Windows: 깔끔한 배경 |
| **캡처 도구** | macOS `Cmd+Shift+4`, Windows Snipping Tool, 또는 Cleanshot X |
| **해상도** | Retina 2x (960x1040px 실제 출력) 또는 1x (480x520px) |
| **형식** | PNG → 빌드 시 WebP 자동 변환 |
| **후처리** | 불필요한 OS 크롬 제거, 그림자 제거, 일관된 크롭 |

### 캡처할 장면 6종

| # | 장면 | 게임 내 상태 | 포인트 |
|---|------|-------------|--------|
| 1 | 메인 화면 | 네모 idle + 방 Lv.3~4 + 가구 3~4개 배치 | 가장 예쁜 방 상태로 셋업 |
| 2 | 채팅 | 채팅 오버레이 열린 상태 + 2~3턴 대화 | 네모의 귀여운 답변이 보이게 |
| 3 | 가챠 | 뽑기 결과 화면 (레어 이상 가구) | 연출 이펙트가 보이는 순간 |
| 4 | 꾸미기 모드 | 하단 인벤토리 + 가구 드래그 중 | 인터랙션 느낌 전달 |
| 5 | 러너 게임 | 게임 진행 중 (코인 수집 장면) | 속도감 있는 순간 |
| 6 | 마켓 | 아이템 목록 + 구매 가능 상태 | 다양한 아이템이 보이게 |
